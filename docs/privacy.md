# 隐私说明与自查清单

## 一、数据流向

| 环节 | 数据 | 去哪 |
|---|---|---|
| 抽音 | 音频 | **只在本机临时目录**，跑完删除 |
| 转写 | 音频 | **只在本机**（faster-whisper 本地推理，不联网） |
| 翻译 | **字幕文本** | 发给你配置的翻译后端 |
| 输出 | 字幕 | 本机 |

**视频文件和音频文件永远不会离开你的机器。** 发给翻译后端的只有字幕文本，
每批 ≤25 条、≤1100 字符。文件名、封面、路径都不发送。

## 二、本机上的明文（真正的风险在这里）

| 文件 | 敏感度 | 说明 |
|---|---|---|
| `*.wav` | ⚠️ **高** | 完整 16k 单声道音频，**能还原全部人声** |
| `*.segs.json` | ⚠️ 中 | 原文 + 译文全明文 |
| `*.srt` | 正常 | 你要的字幕本身 |
| `*.meta.json` | 低 | 只有语言代码和时间戳 |

**默认跑完自动删除前两项。** 要保留加 `--keep-temp`（换目标语言重翻时能省一次识别）。

## 三、用云 API 时的注意

字幕文本会经过第三方服务商。涉密或敏感内容请：

1. 用**本地 Ollama**（`--provider ollama`，数据不出内网）
2. 或只用 `--skip-translate` 生成原文字幕，不做翻译

## 四、自查：后端到底记不记日志

以 Ollama 为例（它是纯推理服务，**没有对话历史功能**）：
默认只写 HTTP 访问日志（时间 / 状态码 / 耗时 / IP / 路由），**不记请求正文**。
但如果开了 `OLLAMA_DEBUG` 就可能记录正文——可以自己发一个标记去搜：

```powershell
# 1) 发一个带唯一标记的请求
curl -X POST http://<你的Ollama地址>/api/chat -H "Content-Type: application/json" `
  -d '{"model":"qwen3:8b","stream":false,"messages":[{"role":"user","content":"VSUBPROBE123 只回复：收到"}]}'

# 2) 在那台机器上搜日志里有没有这个标记
#    Ollama 日志通常在：
#    Windows: %LOCALAPPDATA%\Ollama\server.log
#    Linux:   journalctl -u ollama | grep VSUBPROBE123
# 搜不到 = 没记正文；搜到了 = 关掉 OLLAMA_DEBUG 再测
```

## 五、发布/分享字幕前

- 字幕是纯文本，里面可能有姓名、地名、机构名——发之前搜一遍
- 不要用带个人标识的文件名（比如工号、姓名拼音）当仓库名或示例文件名
